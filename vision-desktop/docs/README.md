# Vision YOLO, easy setup

Train and use an Ultralytics YOLO detector (YOLO26 by default) with one config file and four steps.

**Quick start (two clicks, no typing):**
1. Right-click `00.Setup_env.ps1` and choose **Run with PowerShell**. Wait. It installs Python 3.12 (if missing) and everything else, then opens the GUI.
2. Next times: just double-click `app.py`. If the environment is missing or broken (for example the folder was copied from another PC), it runs the setup for you.

Moving to another PC: copy this whole folder, then do step 1 there. Needs internet and, for an NVIDIA GPU, the NVIDIA driver. If Windows opens `.ps1` in Notepad on double-click, that is normal; use the right-click menu. In the GUI, the buttons `1. Prepare dataset`, `2. Run Train`, `3. Predict` run the four steps below, so you never type a command. The command lines in this guide are the same thing for people who prefer a terminal.

## Folder map

```
00.Setup_env.ps1     START HERE: installs on first run, then opens the GUI
app.py               the GUI (opened by the line above)
configuration/       config.yaml = the ONE settings file (the GUI edits it), requirements.txt
docs/                this guide
scripts/             the engine, you never need to run these by hand:
  prepare_dataset.py   step 2  dataset
  train.py             step 3  training
  predict.py           step 4  inference
  core.py              shared code: paths, hardware auto-detect, dataset split
  test_core.py         self-check for core.py

data/classes.txt     your class names, one per line
data/raw/images      PUT YOUR IMAGES HERE
data/raw/labels      PUT YOUR YOLO .txt LABELS HERE (same file name as the image)
data/dataset         generated by step 2 (do not edit)
input/               images or videos to run the trained model on
models/              downloaded weights (auto)
runs/<run_name>/     training results; weights/best.pt is your model
outputs/predict/     prediction results
```

All paths are set under `paths:` in `configuration/config.yaml`. Relative means inside this folder; a full path such as `D:/datasets` also works.

## 1. Set up the environment

1. If you have an NVIDIA GPU, install the current driver first (`nvidia-smi` must work).
2. In PowerShell in this folder (run it again any time to repair the install):

```powershell
.\00.Setup_env.ps1
```

It installs Python 3.12 if no suitable Python (3.11 to 3.13) is found, creates `.venv`, installs the right PyTorch (CUDA if it finds an NVIDIA GPU, otherwise CPU), installs the requirements, and prints a hardware report.

## 2. Prepare the dataset

1. Write your class names in `data/classes.txt`, one per line (line 1 = class 0).
2. Copy images to `data/raw/images` and YOLO labels to `data/raw/labels`. An image without a label file counts as background.
3. Optional but important: if several images come from the same physical item, set `split.group_regex` in `configuration/config.yaml` so they land in the same split. Group 1 of the regex is the item id. Example for names like `part-0042_top.png` and `part-0042_side.png`: `'-(\d{4})_'`. Without this, train and val share items and your scores look better than they are.
4. Press `1. Prepare dataset` in the GUI, or run:

```powershell
.\.venv\Scripts\python scripts\prepare_dataset.py
```

It splits into `data/dataset/train|val|test` and writes `dataset.yaml`. Your raw files are never changed or deleted. Re-running rebuilds `data/dataset`.

Already split into train/val/test? Put them in `data/dataset/{train,val,test}/{images,labels}`, leave `data/raw/images` empty, and run the same command; it only writes `dataset.yaml`.

## 3. Train

Press `2. Run Train` in the GUI, or run:

```powershell
.\.venv\Scripts\python scripts\train.py
```

Everything comes from `configuration/config.yaml`. Results: `runs/<run_name>/` (`weights/best.pt`, curves, metrics). The first run downloads the base weights into `models/`.

### What `auto` does

Set a value to `auto` and it is chosen from what this PC has free right now. Type a number to override.

| Setting | Rule |
|---|---|
| device | first NVIDIA GPU, else Apple MPS, else CPU |
| batch | free VRAM x 0.8 minus 1.5 GB, divided by the model size and `imgsz` memory cost, rounded down to a power of 2 (2 to 64). CPU: 8 |
| workers | half the CPU threads, max 8 with GPU, max 4 on CPU |
| cache | `ram` if the resized training set fits in 40% of free RAM, else `disk` |
| amp | on for NVIDIA GPUs only |

The GUI shows what it will pick (panel above the buttons, updated every second). Terminal: `.\.venv\Scripts\python scripts\core.py`. Out of memory anyway? Set `batch` to half, or lower `imgsz`.

Any other Ultralytics argument (`lr0`, `hsv_v`, `degrees`, ...) can be added under `train:`.

## 4. Use the model

Put images, a video, or a folder in `input/` (or change `predict.source` in the GUI), then press `3. Predict`, or run:

```powershell
.\.venv\Scripts\python scripts\predict.py
```

It uses the newest `runs/*/weights/best.pt`. Annotated results and `.txt` boxes go to `outputs/predict/` (`Open results` in the GUI opens the runs folder). To choose explicitly in the terminal:

```powershell
.\.venv\Scripts\python scripts\predict.py --weights runs/exp/weights/best.pt --source D:/photos/test.jpg
```

From your own Python code:

```python
from ultralytics import YOLO
model = YOLO("runs/exp/weights/best.pt")
for r in model("input/photo.png", conf=0.25):
    for box in r.boxes:
        print(r.names[int(box.cls)], float(box.conf), box.xyxy.tolist())
```

## The GUI

Opens at the end of the setup, and later by double-clicking `app.py`. One tab per section of `configuration/config.yaml`, a live hardware panel with the `auto` values, and buttons for Setup, Prepare, Train, Predict, Stop. Edit a field, press a button, watch the log. Saving from the GUI rewrites `config.yaml` and drops its comments; this README documents every key.

## Change the model

Set `model:` in `configuration/config.yaml` (dropdown in the GUI). That is the only change needed:

| Want | Set `model:` to |
|---|---|
| YOLO26 small / medium | `yolo26s.pt` / `yolo26m.pt` |
| YOLO11 | `yolo11n.pt` |
| YOLOv10, v9, v8 | `yolov10n.pt`, `yolov9s.pt`, `yolov8n.pt` |
| Train from scratch | `yolo26n.yaml` |
| Your own trained model | `runs/exp/weights/best.pt` |

Add more names to `model_presets` to show them in the dropdown. Letter at the end (n, s, m, l, x) is how `auto` estimates memory; bigger letter = more VRAM and slower. Note: the model family is called YOLO26 by Ultralytics (not "v26"), and it needs `ultralytics>=8.4`.

## Common problems

| Problem | Fix |
|---|---|
| CUDA out of memory | lower `batch` or `imgsz`, or close other GPU apps (auto uses free VRAM at start) |
| "paging file too small" on Windows | set `workers` to 2 or 0 |
| Training shows device `cpu` on a GPU PC | torch is the CPU build; rerun `00.Setup_env.ps1` after installing the NVIDIA driver (delete `.venv` first) |
| Tiny objects are missed | raise `imgsz` (960, 1152), lower `scale` |
| Metrics suspiciously high | set `split.group_regex` (see step 2) |
